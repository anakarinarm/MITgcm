# `intTides_PBC_smalldom_HR`

Last updated: 2026-07-06

This directory contains the MITgcm configurations developed for high-resolution
internal-tide simulations near Todos Santos Bay / Ensenada, with emphasis on
the canyon near approximately `243.25 E, 31.785 N`.

## Provenance and transparency

This README was generated by Codex, working interactively with Karina Ramos
Musalem, as a synthesis of the configuration tests, diagnostic scripts,
discussion, and summary files in this experiment directory. It is intended as a
transparent “memory file” for the project: a guide to what was tried, what was
learned, and which configuration is currently considered the production
baseline.

The more detailed source notes remain in the run-specific README files and
summary documents linked below. If this README and a run-specific file disagree,
trust the run-specific file for exact namelist/file details and update this
summary.

## Scientific goal

The working goal is to simulate internal tide / internal wave generation and
propagation around the Todos Santos Bay canyon system while preserving enough
diagnostics to evaluate:

- barotropic-to-baroclinic energy conversion;
- baroclinic energy fluxes;
- momentum budgets using vector-invariant MITgcm momentum terms;
- sensitivity to tidal forcing amplitude.

The canyon marker used in recent plots is:

```text
lon = 243.25 E
lat = 31.785 N
```

## Current recommended production baseline

The current production baseline is:

```text
runProd_HR_fullTPXO_gebcoW11775_momentumEnergy
```

This configuration was promoted from:

```text
runBC_HR_fullTPXO_obeta_gebcoW11775_pilot
```

after the HR animations and boundary diagnostics looked acceptable. In
particular, the strong internal-wave generation site close to the western side
looked physically tied to real offshore topography and far enough from the open
boundary that it should be retained rather than automatically treated as a
boundary artifact.

### Production geometry

- Grid: `750 x 720 x 60`.
- Physical domain: `690 x 600`.
- Sponge: `60` stretched cells on W/S/N.
- Physical west edge: `242.25 E` = `117.75 W`.
- Physical south edge: `31.25 N`.
- East boundary: closed land wall.
- Bathymetry: GEBCO, with W/S/N sponge bathymetry flattened normal to the
  boundaries.
- Boundary forcing: full TPXO M2 SSH + barotropic velocity records on W/S/N.
- OBCS: prescribed SSH/velocity with nonlinear free surface/r*, momentum-only
  sponge, no Stevens in the prescribed-SSH configuration.

### Production diagnostics

The production run writes:

- `diag_state_3d`: `UVEL`, `VVEL`, `WVEL`, mass velocities, `THETA`, `SALT`,
  `RHOAnoma`, `PHIHYD`, `UVELPHI`, `VVELPHI`;
- `diag_state_2d`: `ETAN`, `PHIBOT`;
- `diag_mom_budget`: direct momentum-budget tendency/forcing/dissipation
  terms;
- `diag_mom_vecinv`: vector-invariant momentum terms, KE/vorticity, side drag,
  and bottom drag.

Output begins after the 3-M2 ramp:

```text
M2 period = 44712 s
timePhase = 134136 s = 3 M2
frequency = 5589 s = M2/8
endTime   = 357696 s = 8 M2
```

So the first baseline saves five M2 periods of analysis output.

## Boundary-condition development history

The detailed boundary-test history is documented in:

```text
BOUNDARY_TEST_SUMMARY.md
```

The short version is that the project explored several boundary strategies
before settling on the present HR full-TPXO GEBCO W117.75 candidate:

1. Original TPXO velocity-only boundary files on the small domain showed
   unbalanced ETAN behavior and hard-to-interpret boundary fluxes.
2. Sponge layers helped, but sponge strength alone could not fix inconsistent
   or over-constrained boundary forcing.
3. Telescopic W/S/N sponge cells made numerical sense, especially when the
   sponge bathymetry was flattened normal to the boundary.
4. Full-boundary TPXO with prescribed SSH/elevation (`OB*etaFile`) was initially
   suspicious in the small old domain because it could impose a standing
   free-surface signal.
5. No-SSH balanced/radiative TPXO velocity tests reduced ETAN problems but still
   showed west-side contamination.
6. Analytical south-entering M2 tests were useful as controlled idealized cases.
7. The project then revisited full TPXO after extending the physical western
   boundary to `117.75 W` using broader GEBCO bathymetry. In that larger domain,
   the full TPXO SSH+velocity setup looked much more physically plausible in HR.

The major lesson is not “TPXO is bad.” The lesson is that a large-scale tidal
solution can over-constrain a small regional model if imposed too close to the
target physics. Moving the western boundary offshore and giving the model a
larger physical domain plus a stretched sponge made TPXO forcing more credible.

## Amphidromic-point evaluations

The amphidromic-point comparisons were done after the original boundary master
summary and are saved separately in:

```text
bc_eta_tpxo_amphidrome_comparison/bc_eta_tpxo_amphidrome_summary.md
runProd_HR_analyticM2_A001_momentumEnergy/amphidrome_tpxo_comparison/m2_amphidrome_tpxo_comparison_summary.md
```

### What was tested

The analysis compared fitted M2 SSH amplitude and phase in the model against
TPXO9. It searched for low-|η| points and checked phase winding around those
points. A physically meaningful amphidromic point should combine:

- very small SSH amplitude;
- phase winding near `±2π` around the point;
- consistency with TPXO if the feature is inherited from the regional tide.

### Key finding from LR boundary tests

Some earlier TPXO-forced boundary tests produced model SSH nodes with nearly
zero `|η|` and approximately `2π` phase winding even though TPXO itself had
large `|η|` and no comparable winding at the same location. That means those
nodes were generated by the model/boundary configuration, not inherited from
TPXO.

Example from the compact comparison:

- `runBC_LR_fullTPXO_obeta_balanced`
  - model min near `243.2024 E, 31.5981 N`;
  - model `|η|min ≈ 8.9e-05 m`;
  - model winding ≈ `2π`;
  - TPXO `|η|` at that point ≈ `0.49 m`;
  - TPXO winding there = `0`.

### Key finding from analytical HR production comparison

The analytical HR production run had a model low-|η| point, but the comparison
to TPXO showed it was not a TPXO-inherited amphidrome:

- model minimum `|η|`:
  - lon/lat ≈ `242.9049 E, 31.4144 N`;
  - `|η| ≈ 1.19e-05 m`;
  - phase winding at radius 8 ≈ `2π`;
- TPXO at that same location:
  - `|η| ≈ 0.483 m`;
  - phase winding = `0`.

This supported the interpretation that the analytical/no-SSH configuration was
producing its own free-surface phase geometry rather than reproducing TPXO.

### Current interpretation

The amphidrome diagnostics were important because they showed that a visually
nice Kelvin-wave-like phase propagation can still contain a model-generated SSH
node. That realization helped motivate the later return to TPXO SSH+velocity
forcing, but only after enlarging the western domain with GEBCO W117.75.

For the current HR full-TPXO GEBCO W117.75 production candidate, the animations
looked better than the coarse run and did not show the same problematic
configuration-induced amphidrome concern that motivated the earlier detour.

## Western-boundary/topography issue

A large internal-wave generation site appears near the western side of the HR
domain, around offshore topography near `31.6 N`. Earlier conversion and
animation diagnostics suggested this could be a real remote generation site,
not merely open-boundary leakage.

This was one reason the western boundary was moved farther offshore to
`117.75 W`: it places the forcing boundary farther from the topographic
generation site while keeping that site inside the physical domain. The sponge
bathymetry is flattened normal to the boundaries so that the sponge itself does
not introduce artificial cross-boundary topographic generation.

    horizontal speed with velocity quivers;

  - barotropic-to-baroclinic conversion processing;
- `plot_m2_barotropic_tide_diagnostics.py`
  - M2 ETAN and barotropic velocity diagnostics;
- `plot_depth_integrated_momentum_phase_maps.py`
  - depth-integrated momentum-budget phase maps;
- `check_boundary_reflections.py`
  - bulk boundary pressure-work / reflection proxy used in boundary tests;
- `modal_characteristic_decomposition.py`
  - approximate modal inward/outward characteristic decomposition.

Use `python`, not `python3`, on this computer.

## Practical notes

- Large binary input files and model output are not intended to be committed to
  git.
- Production output is preferably written to `/Volumes/LaCie` through an
  `output` symlink in each run directory.
- The HR full-TPXO GEBCO W117.75 executable uses:

```text
code_hr_obeta_gebcoW11775
build_hr_obeta_gebcoW11775
```

- The build uses 20 MPI ranks:

```text
sNx = 150
sNy = 180
nPx = 5
nPy = 4
Nx  = 750
Ny  = 720
Nr  = 60
```

- The local `DIAGNOSTICS_SIZE.h` is required so the diagnostics package has
  enough storage for the production diagnostic lists.
